# 关于我：在机器的秩序里写字

分布式系统里有种很动人的时刻：所有机器都停下来，等一个迟到的同伴。

我做区块链底层研发，主力语言是 Go。这份工作说复杂也复杂，说简单也简单——让一群互不信任的机器，对同一本账达成一致。共识算法、账本存储、网络同步，日复一日，在那些「离业务很远、离机器很近」的地方打转。

这篇是写给新读者的自我介绍：我是谁、为什么写字，以及这个小站里都有些什么。

<!-- more -->

## 我是谁

代码写久了，会生出一些旁人看来古怪的偏好：读一段日志比读一段散文安心，看见内存曲线平稳得像一条直线会莫名欣慰，对某些词格外敏感——「有序」「最终一致」「恰好一次」，这些词在日常语境里是修辞，落到这里就是承诺，写错了要还。

对这份手艺的理解，这些年改过三次。最开始只求它能跑起来；后来求它跑得漂亮，变量要对齐，函数要短，抽象要干净；再后来才慢慢懂得，最难的既不是跑起来，也不是跑得漂亮，而是知道它该不该存在、该长成什么形状。

技术选型的答案常常不在技术里，而在你要解决的问题里。

## 我为什么写字

写博客这件事，最初是为了给未来的自己留一张字条。

同一个坑，第一次掉进去叫运气不好，第二次叫记性不好，第三次就只能是懒了。

写得久了才发现，它的意义比「备忘」大得多。脑子里那些东西，多半是一团雾；落到纸上、变成句子，轮廓才一点点显出来。写着写着会撞见两种时刻：一种是「原来我是这么想的」，另一种更珍贵——「这里我其实没想明白」。后者往往就藏在写得最顺畅的那一段后面。

写字还有一种隐蔽的好处：它会逼你诚实。含糊的地方，句子会先露馅。

## 一半流动，一半沉淀

这个站是我给自己开的一块地，一半用来流动，一半用来沉淀。「博客」是流动的那半，记录我此刻在想什么；「知识库」是沉淀的那半，整理我长期相信什么。

流动的那半，摊开来是这几块：

- [博客](/blog/)：Go、并发、系统设计、区块链，148 篇，每篇都配可运行的示例代码，放在仓库的 `example/` 目录里，clone 下来就能跑；
- [知识库](/knowledge/)：从技术能力到思维方法的七大能力域，按「将来能不能用上」重新组织过的结构，不是笔记的堆砌；
- [学习笔记](/design-patterns/)：软考·系统架构师的备考笔记，加上 23 种 GoF 设计模式的系统整理——更关心「为什么」和「什么时候别用」；
- [Workbench](/workbench/)：自研的个人开发工作台，文件浏览、Todo 看板、用户与组织、分享下载，Go + SQLite 单二进制，数据完全自持。

流动的部分难免犯错，沉淀的部分也会过时。所以我给每条知识都标了状态——有效、草稿、待更新。承认自己会错，比假装自己一直对，要省力得多：前者只是改一篇文章，后者要拆掉一整座脚手架。

至于常用的家伙，摆在 [关于我](/about/) 那一页：Go 为主，Java 和 Python 备用；Docker、Kubernetes 和 CI/CD 管交付；MySQL、PostgreSQL、Redis、MongoDB 管存储；再往上一层，是共识算法与密码学。

## 写在最后

我常常觉得，做技术和写文章是同一件事的两面：都在混沌里找结构，在结构里找秩序，最后还要把这份秩序讲给别人听。讲不清楚，多半是因为自己还没想清楚。

所以这个站会一直更新下去。它是我的另一条链——没有共识算法，没有账本，也没有需要等待的同伴；只有一些写在时间里的句子，安静地排在那儿，等某个恰好路过的人读上一会儿。

如果这些句子里有一句对你有用，那就不算白写。
