# Markdown 规范检查清单

> 强制执行：所有知识库内容编辑前必须通过此清单检查

## 前置检查（编辑前）

### ✅ 列表格式检查
- [ ] **有序列表**：序号后必须换行，避免渲染到同一行
  ```markdown
  # ✅ 正确
  1. 第一项
  2. 第二项
  
  # ❌ 错误
  1. 第一项 2. 第二项
  ```
- [ ] **无序列表**：每个项目独立一行
- [ ] **嵌套列表**：缩进 2 个空格

### ✅ 代码块检查
- [ ] **语言标签**：必须带语言标签 ` ```go ` / ` ```sql `
- [ ] **文件标题**：长代码加 `title="filename"`
- [ ] **行内代码**：短代码用 `` ` ` ``

### ✅ 段落格式检查
- [ ] **段落长度**：单段 2-4 句，不超过 5 句
- [ ] **段间间距**：段间空一行
- [ ] **加粗格式**：`**text**` 前后必须留空格

## 后置验证（编辑后）

### ✅ 整体结构验证
- [ ] **章节标题**：用 `##`，不滥用 `###`
- [ ] **章节数量**：3-6 个为佳
- [ ] **技术名词**：保留英文原文（API、goroutine）

### ✅ Material for MkDocs 语法验证
- [ ] **警告框**：正确使用 `!!! info/warning/success`
- [ ] **选项卡**：`=== "标签标题"` 格式正确
- [ ] **高亮文本**：`==高亮内容==` 使用恰当

## 紧急修复流程

### 🔴 发现问题时
1. **立即停止**：暂停当前编辑
2. **检查规范**：对照此清单逐项检查
3. **修复问题**：使用 `replace_in_file` 工具修复
4. **重新验证**：修复后再次检查

### 🟡 预防措施
- **编辑前必读**：每次编辑前阅读此清单
- **主动检查**：不要等待用户发现问题
- **规范优先**：规范检查优先于功能实现

## 违规后果

❌ **严重违规**：列表格式错误导致渲染问题
❌ **中等违规**：代码块缺少语言标签
❌ **轻微违规**：段落长度超标

**处理原则**：发现违规立即修复，不得推延
