# Skill: knowledge-curator

> **目标**：让 AI 拿到**任意内容**（博客、对话、笔记、文件），自动**分类、提炼、归档**到正确子域，并能**检索**整个知识库。
>
> **重要**：知识库内容的编写风格必须基于 blog-writer 技能中的 Markdown 规范，特别是列表序号需要换行的要求。

## 触发场景

### 自动检索增强回答（核心能力）
- 收到用户**任何指令**时，自动执行浅层检索（扫描知识库 frontmatter）
- 命中 → 深度阅读 → 将知识库内容加入参考范围，结合 AI 自身知识综合回答
- 未命中 → 以 AI 自身知识直接回答（不打扰用户）
- **例外**（不触发检索）：纯社交寒暄（"你好"、"谢谢"）

### 写入类
- "把这段内容沉淀到知识库"
- "整理这篇博客到知识库"
- "X 这块知识我之前没记录过，帮我建一条"
- "把这次会议结论归档"

### 手动检索类
- "在知识库里搜 X"
- "我之前写过分布式锁的知识在哪"
- "看看知识库里关于 Go 并发有哪些"
- "我有没有总结过 PBFT？"

### 主动评估类
- AI 在回答用户技术问题时，自动评估内容价值
- 若内容具有长期复用价值且知识库未收录 → 主动建议沉淀

## 工作流 A：写入（输入 → 归档）

### 1. 加载规则文件
- `references/domain-map.md` —— 七大域 / 30+ 子域的完整映射
- `references/classification-rules.md` —— 自动归类规则
- `references/frontmatter-template.md` —— 标准 frontmatter

### 2. 判定 domain + subdomain

按 `references/classification-rules.md` 流程判定：
1. **关键词扫描**：标题/正文里的技术词
2. **内容类型识别**：代码块？故事？方法论？
3. **域名优先级**：冲突时按 tech > engineering > thinking > domain > humanities > tools > career
4. **不确定时反问用户**

### 3. 检查子域是否存在
- 子域目录已存在 → 走"追加新条目"流程
- 子域目录不存在 → **询问用户**是否新建子目录（已确认允许自由新建）

### 4. 检查文件冲突
- 同子域下已有同名 `.md` 文件 → 询问用户：覆盖 / 追加 / 改名 / 跳过

### 5. 填充 frontmatter
按 `references/frontmatter-template.md` 标准填写：
```yaml
title: ...
created: YYYY-MM-DD    # 今天
updated: YYYY-MM-DD    # 今天
domain: ...
tags: [...]
difficulty: beginner|intermediate|advanced|expert   # AI 评估
summary: "..."         # 一句话，不超过 80 字
source:                # 可选，关联的博客/书/项目
  - type: blog
    url: /blog/posts/2025/01/19/
    title: "负载均衡设计思路与实践指南"
related:               # 可选
  - /knowledge/tech/languages/go/
```

### 6. 提炼正文（关键！）

**不是直接复制来源内容**，而是要：
- 去掉时间线叙事（"今天我遇到了..."）
- 去掉情感表达（"非常有意思..."）
- 去掉铺垫场景
- **保留**：核心定义、原理、代码、表格、列表
- **重组**：按"背景 → 核心 → 示例 → 注意"的**知识结构**重排
- 控制在 1500-3000 字
- **重要**：知识库内容必须遵循 blog-writer 技能的 Markdown 编写规范，特别是列表序号后必须换行，避免渲染问题

### 7. 写入文件
- 路径：`docs/knowledge/{domain}/{subdomain}/{filename}.md`
- 文件名：小写英文 + 连字符（`load-balancing.md` / `pbft.md`）
- 同主题多文件加后缀：`pbft.md` / `raft.md` / `pow.md`

### 8. 更新索引页（可选但推荐）
- 若新条目所属子域有 `index.md` → **追加一行链接 + 更新数量 badge**
- 若该子域原本无 `index.md` → **新建**（按统一风格）

### 9. 完成报告
- 新文件路径
- 所属域 / 子域
- 关联的来源（博客 URL 等）
- 反向链接：知识库首页统计数字（可选）

## 工作流 B：检索（提问 → 答案）

### 1. 浅层检索（默认）

读取 `references/retrieval-guide.md` 后执行：

1. **解析查询**：提取关键词（中英文都要）
2. **frontmatter 索引**：用 Grep 扫 `docs/knowledge/` 下所有 `title:`、`tags:`、`summary:`
3. **正文前 300 字**：命中 frontmatter 后再看正文首段
4. **结果排序**：按 domain 优先级 + 时间倒序

返回格式：
```
找到 N 条相关知识：

[tech/architecture/distributed/load-balancing.md]
  标题: 负载均衡策略与实现
  标签: Go, 分布式系统, 负载均衡
  摘要: 4 种负载均衡策略对比 + Go 实现
  路径: /knowledge/tech/architecture/distributed/load-balancing/

[thinking/effective-reporting.md]
  ...
```

### 2. 深度检索（用户追问时）

当用户要求"详细说"或浅层结果不足时：
- **读全文**：用 Read 工具读命中的 `.md` 文件
- **语义匹配**：理解上下文，给出综合答案
- **跨域串联**：如果涉及多个子域，列出相关知识形成知识图

### 3. 无结果处理
- 明确告知"知识库未收录"
- 建议是否要**当场沉淀**（转工作流 A）

## 工作流 C：主动评估（对话 → 评估 → 建议）

> **核心能力**：AI 在回答用户问题时，主动评估内容是否值得沉淀到知识库，并在回答末尾给出建议。

### 1. 评估时机

在以下场景中，**每次回答后**都应触发评估：
- 用户提出技术类问题（概念解释、方案对比、原理分析）
- 用户要求代码示例或实现方案
- 用户进行问题排查或调试
- 用户讨论架构设计或最佳实践

**例外**（不触发评估）：
- 纯闲聊或非技术类对话
- 简单的文件操作（创建、删除、移动）
- 纯配置修改（如 CI/CD 配置）
- 用户明确表示只是一次性提问

### 2. 评估标准

对回答内容按以下维度打分（每项 0-2 分，满分 8 分）：

| 维度 | 0 分 | 1 分 | 2 分 |
|------|------|------|------|
| **技术深度** | 浅显常识 | 中等深度 | 深入原理 |
| **复用价值** | 一次性 | 偶尔用到 | 高频复用 |
| **结构化程度** | 碎片化 | 有一定结构 | 体系化知识 |
| **知识库缺口** | 已存在 | 部分覆盖 | 完全未收录 |

**建议阈值**：总分 ≥ 5 分 → 主动建议沉淀

### 3. 建议格式

在回答末尾，用简洁的提示框询问用户：

```
---

> 💡 **知识库建议**：这次讨论涉及 [主题领域] 的内容，是否要我沉淀到知识库中？
> - 存档路径预估：`docs/knowledge/{domain}/{subdomain}/`
> - 如果你同意，我会立即提炼核心内容并归档。
```

**不要**：
- ❌ 长篇大论描述知识库价值
- ❌ 强制或催促用户
- ❌ 在无关对话中使用

**应该**：
- ✅ 简洁明了的一句话建议
- ✅ 给出预估路径让用户心中有数
- ✅ 等待用户确认后再执行写入

### 4. 用户响应处理

| 用户回应 | 处理方式 |
|----------|---------|
| "可以" / "好的" / "沉淀" | 立即执行工作流 A |
| "先等等" / "不用" | 尊重用户决定，不追问 |
| "换个路径" / "放到 X 域" | 按用户要求调整后执行 |
| 忽略 / 继续其他话题 | 不重复提醒 |

## 工作流 D：自动检索增强回答（提问 → 检索 → 回答）

> **核心能力**：AI 在回答技术问题前自动扫描知识库，若命中则深度阅读并结合双源知识（知识库 + AI 自身）给出综合回答。

### 1. 触发条件

**默认行为**：收到用户任何消息后，先执行浅层检索。

**极少数例外**（跳过检索，直接回答）：
- 纯社交寒暄（"你好"、"谢谢"、"再见"）
- 已在当前对话中手动触发过检索且用户问题在同一主题范围内（避免重复）

> 设计原理：浅层 Grep 扫 frontmatter 几乎零成本，不会显著增加响应延迟。即使是"帮我检查这篇文章"这种非明确技术提问的场景，知识库中也可能存在编辑核查清单等可用素材。

### 2. 检索流程

#### 2.1 关键词提取

从用户问题中提取：
- **中文关键词**：直接技术术语
- **英文对应词**：参考 `references/retrieval-guide.md` 同义词表
- **组合关键词**：多个词分别检索再取并集

示例：
- 用户问"分布式锁用 Redis 还是 ZK 好？"
  → 提取：`分布式锁`、`distributed lock`、`Redis`、`ZooKeeper`

#### 2.2 浅层索引扫描（Grep frontmatter）

对提取的每个关键词，用 Grep 扫描 `docs/knowledge/**/*.md`：
- 命中字段：`title:`、`tags:`、`summary:`
- **不要读取文件正文**（性能考虑）

#### 2.3 命中判定与二次筛选

| 命中情况 | 处理方式 |
|---------|---------|
| 命中 ≥ 2 条 | **先不深度阅读**。浅读所有命中文件的 `summary:` 字段，按与用户指令的相关性排序，筛掉明显不相关的条目后，再对保留条目进入步骤 2.4 |
| 命中 1 条且置信度高 | 进入深度阅读（步骤 2.4） |
| 命中 1 条但置信度低 | 标记为"弱命中"，正文只读前 300 字确认相关性 |
| 0 命中 | 跳过知识库，直接以 AI 知识回答，**并在回答末尾用折叠块报告"未命中"** |

> **二次筛选的重要性**：多篇命中时，标题匹配度最高的未必是实际最有用的。例如用户说"检查这篇文章"，`article-editing-checklist.md` 标题直接匹配，但 `structural-reading-note-writing.md`（结构/递进检验）和 `markdown-checklist.md`（格式规范）也可能同样适用。跳过二次筛选 = 遗漏参考范围。

#### 2.4 深度阅读

对二次筛选后保留的文件用 Read 工具读全文：
- 命中 ≥ 3 条且全部相关时，优先读取 `difficulty` 最高的 3 条
- 关注 `related` 字段，若有相关链接也纳入阅读范围
- **深度阅读后，在回答中列出实际引用了哪几篇**（让用户知道哪些命中了、哪些被筛掉了）

### 3. 综合回答

将知识库内容与 AI 自身知识融合：

```
回答结构：

[正文回答内容...]

---

<details>
<summary>📚 知识库查询状态</summary>

| 项目 | 详情 |
|------|------|
| 查询关键词 | {提取的关键词，如未查询则写"未触发查询"} |
| 命中条目 | {命中数} 条 或 "无" |
| 命中文件 | {文件路径列表，未命中写 "—"} |

</details>
```

**强制要求**：
- 每次回答**末尾必须**附上知识库查询状态折叠块（`<details>`），无论命中与否
- 如果未触发检索（寒暄等例外），折叠块中写"未触发查询（纯社交对话）"
- 命中时列出实际文件路径和引用的摘要信息
- 未命中时写"本次未从知识库匹配到相关内容"

### 4. 无命中处理

知识库无命中时：
- 正常以 AI 知识回答
- **在回答末尾用折叠块报告查询状态**（`<details><summary>📚 知识库查询状态</summary>...</details>`）
- 回答结束后，结合工作流 C 评估是否值得沉淀

### 5. 回答后评估

按工作流 C 的标准评估本次回答内容价值，达到阈值时给出沉淀建议。

## 关键决策点

### 子域创建
- **允许 AI 自由新建子域**（用户已确认）
- 命名规则：小写英文 + 连字符（`kafka-basics` / `system-trading`）
- 新建子域时**同步新建 `index.md`**（按统一风格）

### 与博客的边界
- **博客**：时间线叙事 + 个人体验 + 详细过程
- **知识库**：结构化沉淀 + 抽象原理 + 可直接复用

### 状态管理
- `status` 字段**不要**写在 frontmatter（Material 主题会渲染成空圆圈）
- 状态信息**只在内容页**用色块/标签展示
- 如果需要快速区分"是否已审核"等元信息 → 用 `difficulty` 或新增自定义字段

### 知识库不写的内容
- ❌ 时间相关的"今天"（已发生的事）
- ❌ 个人情感表达
- ❌ 与特定博客的强引用（用 `source` 字段关联即可）
- ❌ 过度铺垫的"引子"
