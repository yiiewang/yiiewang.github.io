# 写作风格指南

> 提炼自 cloaks 个人站 128 篇真实博客（2022-2026）。AI 写新博客时务必参照此风格。

## 一、整体基调

### 关键词
- **技术直男风**：理性、不矫情、就事论事
- **幽默犀利**：偶尔冒梗，**不卖萌**
- **少废话**：能用一句说清的不用两句
- **有态度**：敢说"这些算法都是狗屎"（PBFT 文里的原话），敢自嘲

### 避免
- ❌ "在现代软件开发中..."
- ❌ "随着 XXX 的快速发展..."
- ❌ "今天我们来聊聊..."
- ❌ "亲，你学会了吗？"
- ❌ "希望本文对你有所帮助"
- ❌ 空话开头 + 强行总结
- ❌ 过度铺垫的"引子"超过 2 段

## 二、段落规则

### 长度
- **单段 2-4 句**，不超过 5 句
- 段间空一行
- 重要转折或强调 → 单独成段

### 句子
- 平均句长 15-25 字
- 主动语态优先
- 技术名词**保留英文原文**：API、channel、goroutine、leader election
- 中英混排时，英文前后留空格（`Go 语言` 不写 `Go语言`）

## 三、章节结构

### 一篇文章的"骨架"（技术类）
```
1. 是什么（一段话点题）
2. 为什么需要（背景、痛点）
3. 怎么做（核心内容，分 2-4 个子章节）
4. 注意事项/坑（独立小节）
5. 小结（一段话，200 字内）
```

### 章节标题
- 用 `##`，不滥用 `###`
- 标题用 `1.` `2.` 编号或动词开头：原理 / 实现 / 注意事项 / 小结
- 章节数 3-6 个为佳
- 可加 emoji 但克制（一个文章最多 2-3 个 emoji）

### 章节内常用套路
| 套路 | 用法 |
|------|------|
| `!!! tip` | 提炼关键观点、个人理解 |
| `!!! quote` | 引用论文 / 官方文档原文 |
| `!!! warning` | 容易踩的坑 |
| `=== "实现方法"` | 多种实现时用 tab 分组 |

## 四、代码规范

### 什么时候上代码
- 抽象概念必须**先讲清再上代码**
- 关键 API 用法 → 给最小可运行示例
- 同一思路有多个实现 → 用 tab 分组（`=== "方法 1"`）

### 代码块格式
- 必须带语言标签：` ```go ` / ` ```sql ` / ` ```bash `
- 长代码加 `title="filename"`：` ```go title="main.go" `
- 行内短代码用 `` ` ` ``
- 注释用中文（保持与文章语言一致）

## 五、引用与链接

### 外部资料
- 论文 → 标题 + 链接：`[OSDI99](https://...)`
- 官方文档 → 章节名 + 链接
- 书籍 → 《书名》格式

### 站内引用
- 关联博客：用相对路径 `/blog/posts/2025/01/19/`
- 知识库条目：`/knowledge/tech/languages/go/`
- 设计模式：`/design-patterns/creational-patterns/singleton/`

## 六、emoji 使用规则

### 允许用
- 章节标题装饰：`## 🟢 背景` / `## 🔧 实现`
- 列表前的视觉引导：`- ✅ 推荐做法` / `- ⚠️ 注意事项` / `- 💡 小技巧`
- 偶尔的强调：`强烈推荐` 前加 `⭐`

### 不允许
- 满屏 emoji
- 表情符号（😄😂🤣）
- 装饰性 emoji 占用正文 1/3 篇幅

## 七、特有表达习惯

### 招牌句式
- "一句话概括：..."
- "具体到代码层面：..."
- "X 跟这些妖艳贱货完全不同..."（出自 PBFT）
- "具体到实现：..."
- "**重点：** ..."
- "注意，X 不是 Y，是 Z。"

### 数字与公式
- 用代码块的 LaTeX：``$n > 3f$``
- 关键数字加粗：`**3f+1**` 个副本
- 列表用 `-`，**不用 `*`**

## 八、复盘类特别规则

### 与技术类的差异
- **开头用故事/事故**："很多后端同学都遇到过这个场景：..."
- **明确点出痛点**：库存被扣两次、用户权益被重复发放
- **解决方案有取舍**：不只是给"正确答案"，说清楚**为什么是这个而不是那个**

### 复盘文骨架
```
1. 故事开头（一段真实场景）
2. 问题本质（穿透现象看本质）
3. 解决思路（分层次：表层→深层）
4. 落地代码/配置
5. 边界与注意事项
6. 小结（升华到方法论）
```

## 九、自检问题（写完过一遍）

1. 第一段是否在 3 句内说清"是什么 / 为什么"？
2. 有没有空话/废话开头？
3. 章节数是否在 3-6 个？
4. 代码块都有语言标签？
5. 引用都用规范的链接格式？
6. 段落都在 2-4 句？
7. 有没有"今天/我们/聊聊/希望"这类套话？
8. 小结是否点题且有收获感？
