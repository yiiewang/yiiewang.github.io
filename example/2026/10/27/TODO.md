# minibridge TODO 池

从"能跑"到"敢一直开着"的待办清单。每条都有验收标准，做完能自己验。
优先级：P0 止血 → P1 安全 → P2 运维 → P3 协议 → P4 验证 → 底子（知识）。

> **讲法比做完更重要**：面试考的是「为什么这么设计、踩过什么坑、怎么权衡」，不是「能不能写出来」。
> 每一项都用「现象 → 定位 → 方案 → 权衡 → 数据」讲成一个故事。
> 职级对标、薪资区间与进阶路线见 [GROWTH.md](GROWTH.md)。

## P0 先止血（踩过的坑都在这）

> 2026-11-02：四条已全部落地于 `v4-keepalive/`。

- [x] **1. 应用层心跳：`PING/PONG` 帧定时发**
      为什么：空闲约 10 分钟被中间设备（NAT / 安全组）回收长连接
      验收：静置 30 分钟后仍能 `Open` 成功
- [x] **2. 死连接检测 + 自动重连**
      为什么：会话死了客户端不知道，一直刷 `open stream timeout`
      验收：`kill` 服务端进程后，客户端自动恢复，无需手工重启
- [x] **3. 连续失败则退出进程**
      为什么：重连成功前别静默装死
      验收：重连 N 次失败 → 非零退出码，交给 systemd 拉起
- [x] **4. 证书生成带连通性自检**
      为什么：SAN 与 `-server` 实际地址不匹配是反复踩的坑
      验收：`make verify` 里用生成的证书真握一次手（openssl s_client）

## P1 安全工程（README 里"v3 故意不做的事"）

- [ ] **5. 证书吊销 CRL**（可选 OCSP）
      验收：吊销后新握手立刻失败，不必换 CA 全量重签
- [ ] **6. 按客户端证书 CN 授权**（`VerifyPeerCertificate` 里做 per-CN 白名单）
      验收：A 证书只能到 8000，B 证书只能到 22
- [ ] **7. 协议版本协商 + 误连识别**
      验收：连到 HTTP 服务时报"看起来不是 minibridge"并立刻关闭，不挂死
- [ ] **8. 密钥保管**
      验收：`make certs` 后私钥自动 `0600`；`ca.key` 不落服务机，Makefile 有权限检查
- [ ] **9. 限流 + 结构化审计日志**（JSON：CN / target / 字节 / 时长）
      验收：单证书连接数、字节数上限生效；日志能按 CN 聚合统计
- [ ] **10. 证书有效期 365 → 30/90 天 + 到期告警**
      验收：过期前日志告警，轮换脚本能跑通

## P2 运维（决定它能不能一直开着）

- [ ] **11. systemd unit**：非 root 用户、`Restart=always`、日志轮转
      验收：reboot 后自起，崩溃自拉
- [ ] **12. 可观测性**：`/metrics`（连接数 / 流数 / 字节 / 握手耗时）+ pprof 开关
      验收：能随时回答"现在几条流、跑了多少字节"
- [ ] **13. 部署 Makefile**：`build` → 分发客户端证书 → 版本对齐校验
      验收：一条命令把客户端配好
- [ ] **14. 优雅退出**：先停 accept，等已有流结束
      验收：升级时不断已有连接

## 底子（不是代码 TODO，是能力 TODO）

按"解释你已见过的现象"排序，性价比最高：

- [ ] **TCP 状态机** —— 已撞见 `FIN-WAIT-2` / `CLOSE-WAIT`，值得系统过一遍（含 `tcp_fin_timeout`、`ip_local_port_range`）
- [ ] **TLS 1.3 握手**（RFC 8446 §2）—— 重点：为什么 1.3 里证书是加密的、0-RTT 的代价
- [ ] **抓包**：tcpdump BPF 语法、Wireshark 跟随流、`SSLKEYLOGFILE` 解密
- [ ] **PKI 实务**：链校验路径、EKU / SAN / basicConstraints 的实际效果、CRL vs OCSP
- [ ] **SSH 体系**：RFC 4253/4254 三层 + channels；`sshd_config` 加固（`PermitOpen`、`ForceCommand`、证书认证、KRL）
- [ ] **Linux**：systemd、nftables、netns、sysctl 调优、文件权限 / capability
- [ ] **Go**：pprof / bench、`-race`、fuzz、context 超时传播

## 建议推进顺序

1. P0 四条 —— 直接解决断线与僵尸会话
2. 同步补 TCP 状态机 + TLS 1.3 握手两块知识，正好解释看到的所有怪现象
3. P1 的吊销 + CN 授权 —— 这是它相对 SSH 真正能占优的地方
4. systemd 那套随时可并行，不依赖代码改动
