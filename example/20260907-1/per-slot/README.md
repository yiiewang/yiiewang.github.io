# per-slot 序列号 MPMC：基础使用与压测

per-slot 序列号版有界 MPMC 无锁队列（Vyukov bounded MPMC）的可运行示例：**每个槽位一台独立状态机**，生产者/消费者各自 CAS 认领游标，无锁、无全局提交边界。

对应博客《[两个生产者之后：给无锁环形队列加同步的三条路](../../../docs/blog/posts/2026/09/07-1.md)》路线三 §4.1；压测结论与《[实测：channel 到底比无锁队列慢多少](../../../docs/blog/posts/2026/09/08-6.md)》互相印证。

## 文件结构

```text
per-slot/
├── mpmc.go   # 队列实现：cell（seq 状态机 + 缓存行补齐）、MPMC、Push/Pop
└── main.go   # 基础使用演示 + 压测框架 + channel 基线对比
```

## 快速开始

`go.mod` 在 `example/` 下，命令需从那里发起：

```bash
cd example
go run ./20260907-1/per-slot                       # 基础使用 + 默认压测矩阵
go run ./20260907-1/per-slot -p 8 -c 8 -n 2000000  # 自定义压测参数
go run -race ./20260907-1/per-slot -n 20000        # 竞态检测（数据量压小）
```

> 注意：不要 `go run main.go`——显式传文件只编译这一个文件，会报 `undefined: entry` / `undefined: NewMPMC`。多文件包请用 `go run .` 或包路径。

### 参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `-p` | 内置矩阵 | 压测生产者数（与 `-c` 同时指定时只跑这一组） |
| `-c` | 内置矩阵 | 压测消费者数 |
| `-n` | 200000 | 每个生产者发送的条数 |
| `-cap` | 1024 | 队列容量（自动向上取整到 2 的幂） |
| `-timeout` | 30s | 单轮压测看门狗超时 |

默认矩阵：`1×1`、`2×2`、`4×4`、`8×8`、`8×1`、`1×8`，每组先跑 MPMC 再跑同参数的 channel 基线。

## 压测在验证什么

- **恰好一次投递**：消息值编码为 `pid<<32 | seq`，消费者用原子 CAS 标志位校验无丢失、无重复、值域合法
- **生产者内 FIFO**：单消费者时逐条校验每个生产者的 seq 连续递增（多消费者下"Pop 认领"与"返回调用方"解耦，逐条顺序不再保证，故只做恰好一次校验）
- **语义对齐**：MPMC 与 channel 基线都是"满/空立即返回失败 + 调用方 `Gosched` 自旋重试"，等待方式一致，吞吐才可比
- **看门狗**：消费停滞超时会中止并报错，避免丢数据时死等

## 参考数据

32 核 Linux（2026-09 实测，机器不同数字会变，趋势不变）：

| 吞吐 ops/s | 1×1 | 2×2 | 4×4 | 8×8 | 8×1 | 1×8 |
|---|---:|---:|---:|---:|---:|---:|
| MPMC | 6.7M | 1.7M | 1.8M | 1.5M | 2.8M | 2.2M |
| channel | 4.2M | 4.0M | 3.6M | 3.0M | 0.85M | 0.98M |

- 单对单：MPMC 快约 60%（少一次锁与调度开销）
- 竞争一上来（2×2 及以上）：**channel 反超约一倍**——队列饱和后 channel 生产者 park 让核，MPMC 生产者自旋重试烧 CPU，等待方式比同步原语本身贵
- 生产者多、消费者少（8×1）：MPMC 明显占优——`Gosched` 自旋恰好匹配"生产者永远有活干"的形态

## 实现要点

- **seq 三态**：`== pos` 可写 → 发布 `pos+1` 可读 → 消费完毕 `pos+cap` 回到可写。一个值同时充当下标与回合数，天然免疫 ABA
- **CAS 认领**：`enqPos`/`deqPos` 各自 CAS 抢占，抢到即独占槽位；发布（先写数据后推 seq）构成 release，消费端读 seq 构成 acquire
- **缓存行补齐**：`cell` 尾部补齐，相邻槽位的 seq/data 写不落同一缓存行，避免 false sharing
- **容量规整**：`roundPow2` 把任意容量向上取整到 2 的幂——`pos & mask` 位技巧的正确性前提

## 边界与注意

- 有界队列：满时 `Push` 返回 `false`（无副作用），空时 `Pop` 返回 `false`，阻塞语义需调用方自建
- 自旋重试适合核不超订阅的场景；核超订阅时改用带休眠的退避或干脆用 channel
- 多消费者下，同一生产者消息的**到达顺序**可能交错（消费认领与返回调用方是两步），需要严格有序时用单消费者，或按 seq 在应用层重排
